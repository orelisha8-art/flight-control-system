# מערכת בקרת טיסות 👻✈️

מערכת ניהול בקרת טיסות בריאקט, בעיצוב "מפחיד בקטע טוב" בהשראת סרטי אנימציה של ליל כל הקדושים. מאפשרת לבקר טיסה לצפות בכל הטיסות באוויר, למיין אותן, להוסיף טיסה חדשה, לשחרר (למחוק) טיסה קיימת — ועכשיו גם לעשות את כל זה בשפה חופשית דרך **פנטום**, עוזר AI שחי בתוך האפליקציה.

## טכנולוגיות

- React 19 + Vite
- React Router (ניתוב בין דפים)
- Tailwind CSS v4, עם עיצוב מותאם ("cartoon sticker": מסגרות עבות, צללים מוסטים, פונטים Rubik / Rubik Wet Paint)
- shadcn/ui (רכיבי UI: Button, Input, Select, Card, Label, Alert)
- **Vercel AI Gateway + AI SDK** — עוזר ה-AI בתוך האפליקציה (`front/api/assistant.js`)

הפרויקט נמצא בתיקיית [`front/`](front/). התיקייה `back/` נשארה ריקה בכוונה — נתוני הטיסות עצמם מנוהלים בצד לקוח בלבד (ללא DB), בהתאם לדרישת התרגיל המקורית. פונקציית ה-`/api` היחידה קיימת אך ורק כדי להסתיר את מפתח ה-AI Gateway מהדפדפן (חובה לכל אינטגרציית AI אמיתית) — היא לא שרת אפליקציה ואינה שומרת שום state.

## הרצה מקומית

```bash
cd front
npm install
npm run dev
```

כדי שגם עוזר ה-AI יעבוד מקומית (לא חובה כדי להריץ את שאר האפליקציה), צריך `vercel dev` במקום `npm run dev`, בתוספת:
```bash
vercel link
vercel env pull
vercel dev
```
ראו [`.env.example`](front/.env.example) לפרטים.

## מבנה הדפים

| נתיב | תיאור |
|---|---|
| `/` | עמוד כניסה — סיסמה קבועה: `12345` |
| `/controlpanel` | כל הטיסות (ברירת מחדל) |
| `/controlpanel/sort` | מיון טיסות — חיפוש חלקי לפי חברת תעופה + מיון לפי מספר נוסעים |
| `/controlpanel/add` | הוספת טיסה חדשה |
| `/controlpanel/delete` | מחיקת (שחרור) טיסה קיימת |

התפריט הצידי מוצג אנכית בצד שמאל במסכים רחבים, והופך לשורה אופקית עליונה במסכים צרים מ-500 פיקסלים.

מצב הטיסות מנוהל בזיכרון בלבד (React Context) — רענון הדף מאפס את רשימת הטיסות לנתוני ברירת המחדל, בהתאם לכך שאין שרת/DB בפרויקט.

## פנטום — עוזר ה-AI 👻

כפתור צף (בכל עמודי `/controlpanel/*`) פותח צ'אט עם "פנטום" — עוזר בקרה מבוסס AI עם תפקיד אמיתי, לא רק גימיק:

- **שאלות חופשיות על מצב השמיים** — "כמה טיסות יש כרגע?", "כמה נוסעים באוויר?" וכו', בהתבסס אך ורק על רשימת הטיסות האמיתית שמועברת לו כקונטקסט (הוא לא ממציא טיסות).
- **ביצוע פעולות בשפה חופשית** — "תוסיף טיסה 12345 של אל על עם 200 נוסעים", "תמחק את טיסה 55555", "קח אותי לעמוד מיון" — הכל מתורגם לפעולה אמיתית באפליקציה.
- **שלב אישור לפני כל שינוי נתונים** — הוספה/מחיקה של טיסה לעולם לא מתבצעת אוטומטית. פנטום מציג כרטיסיית "לאשר / לבטל" עם הנתונים המדויקים שהוא הבין, והבקר (המשתמש) הוא זה שמאשר בפועל. פעולה שאינה משנה נתונים (ניווט בין עמודים) מתבצעת ישירות.

**ארכיטקטורה:** קומפוננטת React (`AssistantWidget`) שולחת את ההודעה + רשימת הטיסות הנוכחית לפונקציית Vercel Serverless אחת (`front/api/assistant.js`), שמפעילה מודל דרך **Vercel AI Gateway** (חבילת `ai`, עם tool-calling ל-3 פעולות: `add_flight`, `delete_flight`, `navigate`). האימות מול ה-Gateway קורה אוטומטית בפרודקשן דרך OIDC של Vercel — אין מפתח API בקוד ואין מפתח שנחשף לדפדפן.

**מגבלה ידועה:** החשבון המחובר הוא free tier של AI Gateway, שחוסם לגמרי מודלים של Claude ומגביל את מגוון המודלים הזמינים. עם המודל הזמין (Gemini 2.5 Flash) גיליתי בבדיקות שהוא לפעמים "ממציא" שם חברת תעופה בעברית במקום להעתיק את מה שהמשתמש כתב, ולפעמים לא מזהה בקשות מחיקה/ניווט בכלל. במקום לרדוף אחרי מודל מושלם תחת מגבלת הזמן, פתרתי את זה ברמת הארכיטקטורה: **שום פעולה שמשנה נתונים לא מתבצעת בלי אישור אנושי מפורש** (ראו כרטיסיית "לאשר/לבטל" למעלה) — כך שגם כשה-AI טועה, הבקר רואה בדיוק מה הוא הבין לפני שזה נכנס למערכת, ושום דבר לא נהרס בשקט. זו גם הפרקטיקה המומלצת בכל אפליקציית AI אג'נטית אמיתית, לא רק פתרון עוקף-באג. עם מפתח AI Gateway בתשלום וגישה למודל חזק יותר (למשל Claude), הדיוק צפוי להשתפר משמעותית — השינוי הנדרש הוא שורת `model:` אחת ב-`front/api/assistant.js`.

## איך השתמשתי ב-AI ולאיזה מטרה

השתמשתי ב-Claude Code (עוזר קידוד מבוסס AI של Anthropic) כדי לבנות את הפרויקט הזה במהירות תחת לחץ זמן של מבחן (3.5 שעות).

**למה השתמשתי ב-AI:**
- **הקמת הפרויקט מאפס** — יצירת אפליקציית Vite+React, התקנה והגדרה של Tailwind v4 ו-shadcn/ui (כולל פתרון בעיית תאימות בין Tailwind v4 לבין ה-CLI של shadcn).
- **כתיבת קוד** — כל קומפוננטות ה-React (עמוד כניסה, תפריט צד רספונסיבי, כרטיסי טיסה, טפסים עם ולידציה) נכתבו על ידי ה-AI לפי המפרט המדויק שקיבלתי (סיסמה, טווחי ערכים, הודעות שגיאה וכו').
- **ולידציה לוגית** — ה-AI תרגם את דרישות הוולידציה בעברית (מספר טיסה מספרי עד 5 ספרות וייחודי, חברה עם לפחות אות אחת, נוסעים בין 1-450) לקוד JavaScript בפועל.
- **Git ו-Deploy** — ה-AI הריץ בשבילי את פקודות ה-git (init, commit) ואת פריסת הפרויקט ל-Vercel דרך ה-CLI, תוך שימוש בחשבונות GitHub ו-Vercel שכבר היו מחוברים במחשב.
- **בקרת איכות** — לפני שסימנתי משימה כגמורה, ה-AI הריץ `npm run build`, שרת פיתוח מקומי, ובדיקות `curl` ישירות מול ה-API כדי לוודא שאין שגיאות קומפילציה או רגרסיות.
- **אינטגרציית AI Gateway** — כשביקשתי להוסיף עוזר AI בתוך האפליקציה, ה-AI חיפש בדוקומנטציה העדכנית של Vercel (`WebFetch`) את הדרך הנכונה לחבר AI Gateway (סוג האימות, שם החבילה, פורמט מזהה המודל) במקום להסתמך על ידע ישן — ה-API של Vercel השתנה מאז ה-knowledge cutoff שלו.
- **דיבוג אמיתי, לא רק כתיבה** — בזמן חיבור העוזר, ה-AI נתקל בכמה בעיות אמיתיות ופתר אותן בעצמו: מודל Claude חסום ב-free tier (עבר למודל זמין), סכימת JSON לא נתמכת ב-OpenAI (עבר לסכימה שטוחה), ואז גילה שמודל Gemini "ממציא" שמות חברות תעופה בעברית — וכשגם מעבר ל-tool-calling לא פתר את זה לגמרי, הוא לא "טיפל בזה בשקט" אלא שינה גישה ארכיטקטונית (שלב אישור אנושי לפני כל פעולה) כדי שהבעיה לא תפגע במשתמש.

**מה לא עשיתי עם AI:** לא ביקשתי מה-AI "לנחש" דרישות שלא נכתבו — כל התנהגות (מסרי שגיאה, נתיבים, טווחי ולידציה) מבוססת ישירות על המפרט שקיבלתי במבחן. שמרתי על שליטה בתהליך: בדקתי כל קובץ שנוצר, ווידאתי שהבנייה (build) עוברת בהצלחה, וקראתי את הקוד לפני ה-commit.

**המטרה:** לנצל AI ככלי האצה לכתיבת קוד "שגרתי" (boilerplate, ניתוב, טפסים) כדי להשקיע את זמן המבחן המוגבל בהבנת הדרישות ובבדיקת התוצאה, ולא בהקלדה ידנית של כל שורת קוד.
